# CITATION RULES

Citation failure is the single most damaging academic gap an examiner can find, and this
repository has a recorded history of it (`REVIEW/00_Examiner_Report.md` §11: "zero resolved
originally"). These rules are mechanical — follow them exactly.

---

## 1. Never invent a citation

Restated from [RESEARCH_INTEGRITY.md](RESEARCH_INTEGRITY.md) because it is the rule most often
broken under pressure: no invented paper, author, year, venue, DOI, or page range; no attaching
an existing key to a claim its source does not make.

If no canonical key fits, write `[CITATION NEEDED]`.

## 3. Bracket format

The build script `07_Thesis/Compiled/build_thesis_docx.py` resolves citations with:

```python
CITE_RE = re.compile(r"\[([A-Za-z]+\d{4}[a-z0-9]*)\]")
```

It matches **single-key brackets only**. Consequences:

| Form | Resolves? | Use |
|---|---|---|
| `[yao2023react]` | ✅ | Always |
| `[yao2023react][lewis2020rag]` | ✅ | Multiple sources — the `Compiled/` convention |
| `[yao2023react; lewis2020rag]` | ❌ **silently fails** | Legacy form in source section files |

**Rule:** in anything destined for the compiled document, use `[a][b]`. The `[a; b]` form
appears widely in draft section files and must be converted before those files feed a build.
Prose in `paper/` uses `[a; b]` freely because `paper/tools/md2tex.py` handles it — check the
destination pipeline before choosing.

## 6. What must be cited

| Situation | Required |
|---|---|
| Any description of a named system | Its key, every time |
| Any empirical claim about the field | Key + honest hedge |
| Any dataset property (MIMIC-IV structure, de-identification, date shifting) | `johnson2023mimic`, `goldberger2000physiobank` |
| Any statistical method | Its key (`delong1988comparing`, `benjamini1995controlling`, …) |
| Any clinical definition (Sepsis-3, SOFA) | `singer2016sepsis3`, `vincent1996sofa` |
| Any metric definition (faithfulness, ECE) | `es2024ragas`, `guo2017calibration` |
| Your own design decisions | Nothing — but say they are yours |

Do **not** cite for: your own architecture, your own rationale, common knowledge within
computer science, or restatements of your own earlier chapters (cross-reference instead).

## 7. Citation placement

- Inline, at the claim, not swept to the end of the paragraph.
- One key per claim where possible; multiple only when the claim genuinely rests on several.
- Never a citation pile ("[a][b][c][d][e]") to look well-read — an examiner reads it as padding.
- Quotations carry the key **and** a locator (section or page).

## 8. Reference list format

IEEE numbered style, permitted by DOPS for Computer Science
(`07_Thesis/Thesis_Formatting_Guide.md` §10):

- In-text `[n]`, numbered by order of first appearance.
- Reference list in citation order, hanging indent 0.5″.
- DOI as `https://doi.org/…` whenever available.
- Never alter citation content when reformatting — style only.

APA 7 applies to non-CS work only; it is the DOPS default elsewhere.
